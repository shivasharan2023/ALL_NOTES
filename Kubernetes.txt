#### Config maps ####
A ConfigMap in Kubernetes is an API object used to store non-confidential data in key-value pairs. It allows you to decouple environment-specific configuration from your container images, making your applications easily portable. ConfigMaps can be consumed by Pods as environment variables, command-line arguments, or as configuration files in a volume.

#### Rolling Update in Kubernetes ####
A rolling update in Kubernetes allows you to update your application without any downtime by incrementally replacing old Pods with new ones. This ensures that your application remains available to users throughout the update process.

##### Section : Multi container pods #######
micro services - decoupling large monolithic application inot subcomponets
enables develop and deploy set of independent, small and reusable code
benefit--> scaleup/down, modify each service as required
some scenarios we may need to couple two or more services(microservices) ex- main app + webserver
this is for two functionalities work together not to couple them 
both share the same lfe cycle
no need to establish volume sharing or services between pods to establish communication between them
How to create??
just add as many containers as required in yaml under containers section of sepc
###Sub Section : multi container pods design pattern
1.co-located containers : 2 containers running in the same pod, when 2 services are dependent on each other
2.init container (regular init container) : when there are initilization steps to be performed before pod starts main application ex. databse to be ready before starting the main application
init container stops
3. side car container : ex.log shipper of sorts that needs to be run along with main app 
sid car conatiner continues to run / ends after main app ends

?? difference between 1 & 3 ==> 1-both starts together 2.side car starts first but ends last
